# 从未开始到第一个模组

> 面向**完全没接触过**这个游戏模组开发的人。按顺序做，大约 30–60 分钟。
> 每一步都有明确的成功判据 —— 卡住时先对照判据，再看 [IL2CPP-Mod-实战笔记.md](IL2CPP-Mod-实战笔记.md) 的对应章节。

---

## 0. 先搞清楚一件事：现在只有 IL2CPP 路线可走

这游戏有**两套互不兼容**的模组方式：

| | 路线 A：官方系统 | **路线 B：MelonLoader** ✅ 当前 |
|---|---|---|
| 适用 | 正式版（Mono） | **Demo 0.46D（IL2CPP）** |
| 加载器 | 游戏内置 | MelonLoader |
| 目标框架 | `netstandard2.1` | **`net6.0`** |
| 模组形态 | 文件夹 + `manifest.xml` + DLL | 裸 `.dll` 丢进 `Mods\` |

**为什么现在只能走 B**：Demo 内部虽然有官方 Mod 系统，但它被硬关了 ——
游戏自己的日志里写着：

```
[ModLoader] Limited build: mod loading disabled.
```

而且它是 IL2CPP 构建（有 `GameAssembly.dll`，**没有** `_Data\Managed\`）。
所以官方文档那套现在**用不了**，照抄会连续踩坑。

> 判断你手上是哪个版本：看游戏目录有没有 `Probably Stolen_Data\Managed\`。
> 有 → Mono（路线 A）；没有且只有 `GameAssembly.dll` → IL2CPP（路线 B）。

## 1. 装 .NET SDK 10

```powershell
winget install Microsoft.DotNet.SDK.10
```

装完**关掉终端重开**（PATH 要刷新），然后验证：

```powershell
dotnet --list-sdks
```

**成功判据**：输出里有 `10.x.x` 一行。

> ⚠️ 只有「运行时」是不够的。如果你看到 `No SDKs were found`，说明装错了包，
> 需要的是 **SDK** 不是 Runtime。
>
> ⚠️ Visual Studio 的 C++ 工作负载**不能**编译 C# —— 命令行 `dotnet` 才是唯一途径。

---

## 2. 装 MelonLoader 到游戏目录

1. 找到游戏目录：Steam 库 → 右键游戏 → 管理 → 浏览本地文件
2. 到 https://github.com/LavaGang/MelonLoader/releases/tag/v0.7.3
   下载 **`MelonLoader.x64.zip`**（不是 x86，不是 Installer）
3. 把它**解压到游戏根目录**（和 `Probably Stolen.exe` 同一层）

**成功判据**：游戏目录里出现 `version.dll` 和 `MelonLoader\` 文件夹。

---

## 3. 启动一次游戏（关键步骤，别跳过）

**这一步会联网生成「代理程序集」，没有它什么都编译不了。**

正常启动游戏，MelonLoader 会弹出一个黑色控制台窗口，花几分钟下载 Cpp2IL
并生成文件。等主菜单出现后关掉游戏。

**成功判据**：

```powershell
$game = "F:\SteamLibrary\steamapps\common\Probably Stolen Demo"   # 换成你的路径
Test-Path "$game\MelonLoader\Il2CppAssemblies\Assembly-CSharp.dll"
```

输出 `True` 就对了。这一步会生成 100 多个 DLL，是编译模组的引用来源。

> 卡在这里的话：看 `$game\MelonLoader\Latest.log`，里面会写它在下什么、失败在哪。
> 首次需要联网，网络不通会失败。

## 4. 把这个模板库 clone 下来当工作区

```powershell
git clone <本仓库地址> ps-mod-dev
cd ps-mod-dev
```

然后用 DSH（或任何 agent 工具）**把 `ps-mod-dev` 目录作为工作区打开**。

**这一步的意义**：库里的 `.agents/skills/` 会被自动发现，
你的 agent 就具备了模组开发的技能；同时你拿到了文档、API 探测工具、构建脚本。

> ⚠️ **必须让这个目录成为工作区根**。DSH 只在「工作区的 `.git` 根」上找 skill，
> 把本库放在别的仓库里的子目录是**不会生效**的。

### 只想留最新快照、不要历史提交？

clone 下来的 `.git` 里有本库的全部提交记录。三种方式可以不要：

```powershell
# 方式 1：浅克隆 —— 只要最新一次提交
git clone --depth 1 <本仓库地址> ps-mod-dev

# 方式 2：不要任何 git 历史（之后要自己建仓再 init）
git clone --depth 1 <本仓库地址> ps-mod-dev
Remove-Item ps-mod-dev\.git -Recurse -Force

# 方式 3：从 GitHub 直接下压缩包（最干净，连 git 都不需要）
gh api repos/<owner>/<repo>/tarball/main | tar -xz
```

**推荐方式 1** —— 保留 git 但没有冗余历史，而且以后本库更新了你可以
`git pull` 拿到新的知识和工具。

## 5. 建第一个模组

在 `workspace/src/` 下建目录，例如 `workspace/src/MyFirstMod/`，放两个文件。

**`MyFirstMod.csproj`**：

```xml
<Project Sdk="Microsoft.NET.Sdk">
  <PropertyGroup>
    <TargetFramework>net6.0</TargetFramework>
    <LangVersion>latest</LangVersion>
    <Nullable>disable</Nullable>
    <ImplicitUsings>disable</ImplicitUsings>
    <AssemblyName>MyFirstMod</AssemblyName>
    <RootNamespace>MyFirstMod</RootNamespace>
    <ProduceReferenceAssembly>false</ProduceReferenceAssembly>
  </PropertyGroup>
</Project>
```

程序集引用**不用自己写** —— 根目录的 `Directory.Build.props` 已经配好了。

**`MyFirstMod.cs`**：

```csharp
using System;
using Il2Cpp;
using MelonLoader;
using UnityEngine;

[assembly: MelonInfo(typeof(MyFirstMod.Mod), "My First Mod", "1.0.0", "你的名字")]
// 游戏名与开发商取自 <游戏>_Data\app.info：第一行开发商，第二行游戏名
// 注意是 "Probably Stolen"，不是 "Probably Stolen Demo"
[assembly: MelonGame("Questing Goose Studio", "Probably Stolen")]

namespace MyFirstMod
{
    public class Mod : MelonMod
    {
        public override void OnInitializeMelon()
        {
            MelonLogger.Msg("[MyFirstMod] 已加载。");
        }

        public override void OnUpdate()
        {
            if (Input.GetKeyDown(KeyCode.F9))
                MelonLogger.Msg("[MyFirstMod] F9 被按下。");
        }
    }
}
```

> ⚠️ **`Il2Cpp.IMod` 不是 interface**，是代理类，所以官方文档那套
> `class X : IMod` 在 IL2CPP 下写不出来。用 `MelonMod` 子类。

## 6. 构建、部署、验证

```powershell
pwsh build\deploy.ps1 -Deploy -Log
```

脚本会：探测游戏目录 → 编译 → 拷进 `<游戏>\Mods\` → 打印 MelonLoader 最新日志。

**成功判据**（日志里出现这几行）：

```
Melon Assembly loaded: '.\Mods\MyFirstMod.dll'
My First Mod v1.0.0
[MyFirstMod] 已加载。
```

然后启动游戏，按 **F9**，应该再多一行 `[MyFirstMod] F9 被按下。`

**到这一步，开发闭环就通了。** 之后就是加功能。

## 7. 加功能之前必读

| 要做的事 | 先看 |
|---|---|
| 查某个功能有没有 API | [实战笔记 §4 API 探测方法论](IL2CPP-Mod-实战笔记.md#4-api-探测方法论) —— **不要凭官方文档写** |
| 理解游戏对象模型（窗口/背包/元素图） | [实战笔记 §3](IL2CPP-Mod-实战笔记.md#3-游戏架构窗口--背包--元素图) —— 「背包不是 Component」这类反直觉事实 |
| 加设置界面 | [实战笔记 §5 用游戏原生框架编写 UI](IL2CPP-Mod-实战笔记.md#5-用游戏原生框架编写-ui) |
| 动手前扫一眼坑 | [实战笔记 §6 踩坑清单](IL2CPP-Mod-实战笔记.md#6-踩坑清单) |

**最容易犯的错**：直接照官方 ModdingGuide 写代码。它描述的是尚未上市的
正式版，本构建**缺其中一大批 API**（`SetModData`、`AddLootEntry`、`PlaySound`、
`SetSpriteAndShapeFromMod`、`ModScanner` 等）。**动手前先查代理程序集。**

## 8. 发布给别人的话

```powershell
pwsh build\pack.ps1 -Mod MyFirstMod
```

会生成 `workspace/dist/MyFirstMod-v1.0.0.zip`，结构是「解压到游戏根目录即用」：

```
MyFirstMod-v1.0.0.zip
├── README.txt            ← 使用者说明（你在 workspace/src/MyFirstMod/README.txt 写）
└── Mods\MyFirstMod.dll
```

脚本会**校验版本号确实写进了 DLL**，避免 zip 名和实际版本对不上。

---

## 你的代码放哪、会不会污染模板库

- **放 `workspace/` 下**，该目录已在 `.gitignore` 里忽略 —— 模板库不会变脏
- 想给模组单独建 git 仓库：在 `workspace/src/MyFirstMod/` 里自己 `git init` 即可
- 模板库更新了（`git pull`）不会碰到你的代码

---

## 卡住了怎么办

1. **先看日志**，别猜：
   - `<游戏>\MelonLoader\Latest.log` —— 模组加载、异常
   - `%USERPROFILE%\AppData\LocalLow\Questing Goose Studio\Probably Stolen\Player.log` —— 游戏自己的日志
2. **对照成功判据** —— 本文每一步都给了
3. **再去查实战笔记的踩坑清单** —— 大概率有人踩过
4. 还是不行就把日志贴出来问
